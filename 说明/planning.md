# 开票日历实施计划

目标：将六张小程序截图转换成桌面/手机可用 Web，修正草稿建模，提供用户/管理员登录、SQL CRUD 和课程文档。

技术：Python 标准库 HTTP 服务 + SQLite + 原生 JS/CSS，同源 API，无安装依赖。SQLite 是实际关系数据库，所有数据通过参数化 SQL 持久化。若课程指定 MySQL，需另外迁移方言；当前不假定课程指定产品。

里程碑：1. 健康检查与静态壳、数据库连接；2. 规范化数据库及种子数据；3. 会话与服务端权限；4. 日历/城市过滤/详情；5. 通用管理员 CRUD 与图片上传；6. API 集成测试及浏览器验收。

范围：剧目/演出批次/场次/角色/演员/开票轮次/售票渠道。无支付、订单、实时余票。演出素材来自截图，仅做课程演示，不声称实时信息。非 agent 项目，无 agent benchmark。

验证：unittest 覆盖登录、越权、CRUD、约束、筛选和上传；node --check；真实浏览器打开并操作。空态、错误、加载和成功均显示。

## 2026-11-11 迭代
新增 30 个明确标注模拟的演出批次，11/12 月各 15 个，每批次 2 场、2 个开票轮次，覆盖五座城市。使用一次性版本记录进行增量导入，保留现有数据与用户修改，重启不重复导入。城市筛选改漏斗按钮、可滚动多选面板，取消/完成/清空分离暂存选择与已应用条件，Escape/点击外部关闭。验证月份分布、场次/轮次数、重启幂等和原有 API 回归。
